# 屏幕录屏（ScreenRecord）插件 —— 使用说明、实现细节与接入指南

> 适用版本：本仓库 `src/plugins/record` 当前实现
> 阅读对象：需要**接入录屏 / 理解实现细节 / 对接上传后端 / 替换上传方式**的前端、测试与后端同学
> 配套源码：`src/plugins/record/`（插件）、`src/api/modules/demo-record.ts`（接口）、`src/mock/demo-record.ts`（本地 mock 后端）、`src/views/vant/VantRecordDemo.vue`（演示页）

---

## 0. 这份文档解决什么

- **怎么用**：在 `main.ts` 安装插件、在业务里 `start/stop`、或用 `recordOperation` 一步包裹业务操作（第 3 章）；
- **实现细节**：底层怎么用 `getDisplayMedia + MediaRecorder` 录屏、状态机怎么流转、为什么这样设计、可测性怎么做的（第 4 章，重点）；
- **后续如何接入**：从 demo 落到真实业务页面需要改哪里、上传器怎么替换成 FormData/OSS 直传、token 怎么注入（第 5 章，重点）；
- **API 怎么调**：上传/列表接口的入参出参与 mock 后端行为（第 6 章）；
- **踩过的坑**：浏览器安全限制（必须用户手势 + HTTPS/localhost）、base64 上传体积、Safari 降级、objectURL 回收等（第 7 章，重点）。

## 1. 插件能做什么（能力边界）

| 能力 | 说明 |
| --- | --- |
| 屏幕录制 | 基于 `navigator.mediaDevices.getDisplayMedia()` 获取屏幕/标签页流，`MediaRecorder` 录制成 `webm`（优先 vp9/vp8，自动回退 mp4） |
| 页面操作发起录屏 | 由用户的一次业务动作（点击/提交）触发 `start()`，结束后（成败均）`stop()` 并上传——即"录屏是业务操作的副作用" |
| 手动起停 | 显式 `start()/pause()/resume()/stop()`，配合本地预览与「停止后自动上传」开关 |
| 业务操作包裹 | `recordOperation(fn)` 把一次业务动作整体包起来：发起即录、结束即停、失败也上传（便于回溯异常现场） |
| 自动上传 | 停止后默认自动把 Blob 经 uploader 上传后端；可关闭开关保留本地副本，手动 `upload()` |
| 上传器可替换 | 默认 base64(JSON) 上传（兼容 mock）；生产可换成 `FormData` 直传 OSS/MinIO，只需替换 `uploader` 或 `createScreenRecordPlugin({ uploader })` |
| 超时保护 | `maxDurationMs` 超时自动停止，避免无限录制 |
| 元数据注入 | `bizType/bizId/title` 等业务字段随上传写入后端，便于检索归类；`userId/name` 缺省由 token 自动注入 |
| 事件订阅 | `on()` 订阅 `statechange/tick/complete/uploading/uploaded/error`，供 UI 实时展示 |

> 与 Track 插件的区别：Track 记录的是**离散 DOM 事件序列**（点哪、输什么），用于回放；ScreenRecord 记录的是**屏幕视频流**（录屏），用于事后直观回溯。两者互补：录屏可附 `bizType` 与 Track 会话关联。

## 2. 架构总览

```
┌──────────────────── 业务触发 ────────────────────┐
│  ① 手动起停：点击「开始录屏」按钮 → record.start()  │
│  ② 业务包裹：record.recordOperation(submitClaim)    │
│       │ 二者都要求在「用户手势」内调用（浏览器限制）  │
└──────────────────────────┬────────────────────────┘
                           ▼
┌──────────── ScreenRecorder（recorder.ts）─────────┐
│  start()                                            │
│   ├─ getDisplayMedia({video, audio}) → MediaStream  │
│   ├─ new MediaRecorder(stream, {mimeType})          │
│   ├─ ondataavailable → chunks.push                 │
│   ├─ recorder.start(timesliceMs) → 周期切片          │
│   ├─ tick 心跳（每 200ms 派发 elapsed）              │
│   └─ 用户点「停止共享」/ maxDuration 超时 → stop()   │
│  stop() → onstop → _finalize()                      │
│   ├─ new Blob(chunks) → URL.createObjectURL         │
│   ├─ 派发 complete（产出 ScreenRecordResult）         │
│   └─ autoUpload? upload()                           │
└──────────────────────────┬────────────────────────┘
                           ▼
┌──────────── Uploader（默认 base64 + JSON）─────────┐
│  blobToBase64(blob) → data:<mime>;base64,<data>      │
│  uploadScreenRecord({ fileName, base64, meta... })   │
│   → POST /demo/screen-record/upload                 │
└──────────────────────────┬────────────────────────┘
                           ▼
              ┌──── 后端 / Mock 后端 ────┐
              │ 解码 base64 → 落盘         │
              │ 返回可访问 URL + fileId    │
              │ GET /demo/screen-record/list 查询 │
              └────────────────────────────┘
```

插件层 `createScreenRecordPlugin` 在 `install` 时：
1. `new ScreenRecorder(options.deps)`；
2. 把插件单例挂到 `app.provide(ScreenRecordKey, plugin)`、`app.config.globalProperties.$screenRecord`、`window.__screenRecord`；
3. 维护一个**模块级单例 `globalPlugin`**，使 `useScreenRecord()` 在任意组件/脚本（甚至未注入 context 时）拿到同一实例。

## 3. 快速开始

### 3.1 安装（main.ts）

```ts
import { createTrackPlugin } from './plugins/track'
import { createScreenRecordPlugin } from './plugins/record'

app.use(createTrackPlugin({ enabled: true }))
// 屏幕录屏插件：默认 autoUpload=true（停止后自动上传）。
// 注意：录屏必须在「用户手势 + HTTPS/localhost」下触发，插件安装后不会自动录制，
// 业务在「页面操作发起」时手动 record.start() / recordOperation()。
app.use(createScreenRecordPlugin({ autoUpload: true }))
app.mount('#app')
```

插件暴露：
- `app.config.globalProperties.$screenRecord`
- `window.__screenRecord`（运行时调试入口，如 `window.__screenRecord.isSupported()`）

### 3.2 在业务里用（手动起停）

```ts
import { useScreenRecord } from '@/plugins/record'

const record = useScreenRecord()

// 必须满足「用户手势」内调用（如绑定在 @click 处理函数里）
async function onStartClick() {
  if (!record.isSupported()) {
    showToast('当前环境不支持屏幕录制')
    return
  }
  await record.start({
    meta: { bizType: 'insurance-claim', bizId: policyNo, title: '投保单提交' },
  })
}

// 业务进行中……（可 record.pause() / record.resume()）

async function onStopClick() {
  // 停止后若插件 autoUpload=true，会自动上传；否则保留本地副本
  const result = await record.stop()
  console.log('本地预览', result?.url, '已上传', result?.uploaded?.url)
}
```

### 3.3 业务操作包裹（最贴近真实诉求）

```ts
// 把一次「投保提交」整体包起来：发起即录屏，结束（无论成败）自动停止并上传
const { operation, result } = await record.recordOperation(
  () => submitClaim(payload),                 // 真实业务函数，返回保单号等
  { meta: { bizType: 'insurance-claim', title: '投保单提交' } },
)

// operation 即 submitClaim 的返回值；如业务抛错，recordOperation 会先上传录屏再向外抛出
console.log('保单号', operation.policyNo)
```

### 3.4 订阅事件（实时 UI）

```ts
const off = record.on((e) => {
  switch (e.type) {
    case 'statechange': state.value = e.state; break           // idle/recording/paused/stopped/error
    case 'tick': elapsed.value = e.elapsedMs; break            // 每 200ms 心跳
    case 'complete': result.value = e.result; break            // 录制产物
    case 'uploading': uploading.value = true; break
    case 'uploaded': uploadedUrl.value = e.result.url; break
    case 'error': console.error(e.error); break
  }
})
// 组件卸载时 off()
```

## 4. 实现细节（核心）

### 4.1 录制技术栈

- **取流**：`navigator.mediaDevices.getDisplayMedia(constraints)`，`constraints = { video: { width:1280, height:720, frameRate:15 }, audio: opts.audio ?? false }`。浏览器会弹「选择共享内容」对话框。
- **录制**：`new MediaRecorder(stream, { mimeType })`。编码优先级 `vp9,opus → vp8,opus → webm → mp4`，通过 `MediaRecorder.isTypeSupported` 探测，不支持时自动回退（见 `recorder.ts` 的 `MIME_CANDIDATES` / `pickMimeType`）。
- **切片**：`recorder.start(opts.timesliceMs ?? 1000)`，每 `timesliceMs` 触发一次 `ondataavailable`，把 `e.data` 推入 `chunks`（体积可控、崩溃可保留已切片段）。
- **停止收尾**：`recorder.stop()` → `onstop` → `_finalize()`：`new Blob(chunks, { type })` → `URL.createObjectURL` → 派发 `complete` → 按需 `upload()`。

### 4.2 状态机

```
        start()                pause()           stop()/用户停止共享/超时
 idle ───────────▶ recording ───────────▶ paused ───────────▶ (onstop)
   ▲                  │  stop()            │ resume()              │
   │                  ▼                    ▼                      ▼
   └────────────── stopped ◀──────── recording ◀────────   _finalize()
                          │
                    upload() → uploaded
   (任意态 recorder.onerror 或 start 失败 → error)
```

- `statechange` 事件携带 `{ state, prev }`，便于 UI 切换。
- `start()` 重入保护：已在 `recording/paused` 时抛「已在录制中」。

### 4.3 依赖注入（可测性关键）

`ScreenRecorder` 构造函数接受 `ScreenRecorderDeps = { getDisplayMedia?, MediaRecorderCtor?, now? }`，使得核心逻辑在 jsdom/Node 下可单测，无需真实浏览器媒体能力：

```ts
// 单测里注入假实现
const fakeStream = {} as MediaStream
const fakeMR = class {
  state = 'inactive'
  mimeType = 'video/webm'
  ondataavailable: any
  onstop: any
  onerror: any
  constructor(_s: any, _o?: any) {}
  start() { this.state = 'recording' }
  stop() { this.state = 'inactive'; this.ondataavailable?.({ data: new Blob(['x']) }); this.onstop?.() }
  pause() {} resume() {}
}
const r = new ScreenRecorder({
  getDisplayMedia: async () => fakeStream,
  MediaRecorderCtor: fakeMR as any,
  now: () => Date.now(),
})
```

`createScreenRecordPlugin({ deps })` 透传同一组依赖（测试用）。

### 4.4 自动上传的双路径设计

为避免「停止即上传」与「业务包裹再上传」两种路径**重复上传**，`_finalize()` 内部统一：

- 若 `autoUpload=true`：在 `_finalize()` 末尾 `await this.upload()`（用调用方注入的 uploader）；
- 若 `autoUpload=false`：仅产出 `ScreenRecordResult`，**不**自动上传，交由调用方（如 `recordOperation` 的 `finally`）显式 `upload()`。

`recordOperation` 内部**强制 `autoUpload=false`**，统一在 `finally` 后 `await this.upload()`，从而可以 `await` 上传完成、并保证「业务失败也上传」：

```ts
async recordOperation(operation, opts) {
  const merged = { ...opts, autoUpload: false }
  await this.start(merged)
  try { opResult = await operation() }
  catch (e) { opErr = e }
  finally { await this.stop() }          // stop 后已产生 result
  try { if (!this._lastResult?.uploaded) await this.upload() } catch { /* 不影响业务 */ }
  if (opErr) throw opErr
  return { result: this._lastResult, operation: opResult! }
}
```

### 4.5 超时与心跳

- `maxDurationMs > 0` 时，`start()` 注册 `setTimeout` 到点自动 `stop()`；`_finalize` / `dispose` 时清理。
- `tick`：每 200ms `setInterval` 派发 `{ type:'tick', elapsedMs }`，供 UI 显示计时；`pause` 时停、`resume` 时续。

### 4.6 资源回收

- 流：停止后 `_cleanupStream()` 调 `stream.getTracks().forEach(t => t.stop())`。
- objectURL：`_finalize` 前先 `revokeObjectURL(旧)`、再建新；`dispose()` 也回收，避免内存泄漏。
- 监听：`dispose()` 清空 `_listeners`。

### 4.7 不支持环境降级

- 构造时检测 `getDisplayMedia` 与 `MediaRecorder` 是否可用，置 `_supported`；
- `start()` 在不支持时**抛可读错误**（而非静默崩溃），UI 通过 `record.isSupported()` 提前提示；
- 演示页 `onMounted` 检测不支持即 `showToast` 并禁用按钮。

## 5. 后续如何接入（真实业务落地）

### 5.1 把 demo 能力迁移到业务页面

最小改动：把你业务页面里「会触发录屏的那次用户手势」替换为 `recordOperation` 包裹。例如投保提交：

```ts
// 原：
async function onSubmit() { await submitClaim(payload) }

// 改：
import { useScreenRecord } from '@/plugins/record'
const record = useScreenRecord()
async function onSubmit() {
  if (!record.isSupported()) return await submitClaim(payload)  // 不支持则降级为纯业务
  const { operation } = await record.recordOperation(
    () => submitClaim(payload),
    { meta: { bizType: 'insurance-claim', bizId: payload.policyNo, title: '投保单提交' } },
  )
  return operation
}
```

按钮需 `:disabled="!record.isSupported()"` 并在 `@click` 内触发（保持用户手势上下文）。

### 5.2 替换上传器为 FormData / OSS 直传（生产推荐）

默认 base64(JSON) 适合 mock 与中小文件；生产大视频建议直接 `FormData` 直传对象存储。两种方式：

**方式 A：在 `createScreenRecordPlugin` 注入全局 uploader**

```ts
import { createScreenRecordPlugin, type ScreenRecordUploader } from '@/plugins/record'

const ossUploader: ScreenRecordUploader = async (blob, meta) => {
  const form = new FormData()
  const ext = meta.mimeType.includes('mp4') ? 'mp4' : 'webm'
  form.append('file', blob, `${meta.title || 'screen'}-${meta.sessionId}${ext}`)
  form.append('bizType', meta.bizType ?? '')
  form.append('sessionId', meta.sessionId)
  form.append('durationMs', String(meta.durationMs))
  const res = await fetch('/api/screen-record/upload', { method: 'POST', body: form })
  const data = await res.json()
  return { url: data.url, fileId: data.fileId, fileName: data.fileName, size: meta.size }
}

app.use(createScreenRecordPlugin({ autoUpload: true, uploader: ossUploader }))
```

**方式 B：单次调用显式传 uploader**

```ts
await record.start({ uploader: ossUploader, meta: { bizType: 'xxx' } })
```

> `ScreenRecordUploader = (blob: Blob, meta: ScreenRecordUploadMeta) => Promise<ScreenRecordUploadResult>`。返回 `{ url, fileId, fileName, size }` 即可。

### 5.3 userId / userName 自动注入

默认上传器从 `getUserInfo()`（token）取 `userId/name` 兜底；业务可显式传 `meta.userId/bizId` 覆盖。后端列表按 `userId` 隔离检索。

### 5.4 与 Track 关联（可选）

录屏的 `sessionId` 与 Track 会话可并存在同一业务单据（`bizId`）下，回放时先放录屏、再放 DOM 事件序列，增强回溯体验。无需额外改插件，只需后端在查询时以 `bizId` 关联两张表。

## 6. API 调用（接口契约）

源码：`src/api/modules/demo-record.ts`。底层 `post/get` 来自 `src/api/request`，自带 axios 拦截与 token 注入。

### 6.1 上传 `uploadScreenRecord`

```ts
uploadScreenRecord(payload: UploadScreenRecordPayload): Promise<ScreenRecordUploadResult>
// POST /demo/screen-record/upload
```

`UploadScreenRecordPayload`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `fileName` | `string` | 文件名（含扩展名） |
| `base64` | `string` | 完整 data URI：`data:<mime>;base64,<data>`（默认上传器由 `blobToBase64` 产出） |
| `mimeType` | `string` | 编码，如 `video/webm` / `video/mp4` |
| `size` | `number` | 字节数 |
| `durationMs` | `number` | 录制时长 ms |
| `sessionId` | `string` | 本次会话 id |
| `title?` | `string` | 录屏标题 |
| `bizType?` | `string` | 业务类型 |
| `bizId?` | `string` | 业务单据 id |
| `userId?` | `string` | 操作人（缺省走 token） |
| `userName?` | `string` | 操作人姓名 |

返回 `ScreenRecordUploadResult`：`{ url, fileId, fileName, size }`。

### 6.2 列表 `listScreenRecords`

```ts
listScreenRecords(userId?: string): Promise<{ list: ScreenRecordListItem[] }>
// GET /demo/screen-record/list?userId=xxx
```

`ScreenRecordListItem`：`{ fileId, fileName, url, size, mimeType, durationMs, createdAt, sessionId, title?, bizType?, userId? }`。

### 6.3 `blobToBase64`（工具）

```ts
blobToBase64(blob: Blob): Promise<string>  // 返回完整 data URI
```

### 6.4 Mock 后端（本地联调）

源码：`src/mock/demo-record.ts`，在 `src/mock/index.ts` 中已注册 `screenRecordMockRoutes`（仅 `dev:mock` 生效）。行为：

- **上传**：解析 JSON body 的 `base64` → 解码 Buffer → 写入 `src/assets/demo-upload/<name>-<ts>.<ext>` → 返回 `{ code:200, data:{ url:'/demo-upload/<file>', fileId, fileName, size } }`。注意：`url` 是相对路径，本地需静态服务暴露 `src/assets/demo-upload` 才能预览下载。
- **列表**：按 `?userId` 可选过滤，返回 `{ code:200, data:{ list } }`。

> Mock 与本仓库 `src/mock/types` 的 `MockRoute` 约定一致（method/url/response）。真实后端需提供等价的 `POST /demo/screen-record/upload` 与 `GET /demo/screen-record/list`。

## 7. 典型问题与排查

### 7.1 ⚠ 浏览器安全限制（最常见）

- **必须用户手势**：`getDisplayMedia` 只能在用户手势（click/tap）的调用栈内触发，否则报 `NotAllowedError`。确保 `record.start()` 在 `@click` 处理函数同步链路里调用，不要在 `await` 之后才调、也不要在 `onMounted` 自动调。
- **必须安全上下文**：HTTPS 或 `localhost`。`http://192.168.x.x` 等内网 IP 会直接不支持（构造时 `_supported=false`）。
- **用户可随时停止共享**：用户点浏览器「停止共享」会结束视频轨 → 监听 `track.onended` 自动 `stop()`。

### 7.2 自动上传开关与 recordOperation 的冲突

- 手动 `start({ autoUpload: false })` 后 `stop()` **不会**自动上传，需显式 `record.upload()`；
- `recordOperation()` 内部强制 `autoUpload:false` 并自行 `upload()`，不要在外面再 `stop()`，否则状态机已 `stopped` 会返回已有 `lastResult`（幂等安全，不会重复录制）。

### 7.3 base64 上传体积

默认上传走 JSON base64，体积约为原文件 ×1.33。大录屏（数分钟 webm）可能超网关 body 上限 → 生产请按 5.2 换 `FormData` 直传。

### 7.4 Safari / 旧浏览器降级

- 构造 `new MediaRecorder(stream, { mimeType })` 失败时，recorder 自动降级为 `new MediaRecorder(stream)`（无 options）。
- 个别浏览器 `isTypeSupported` 抛错，已 try/catch 跳过并回退 `video/webm`。

### 7.5 objectURL 预览失效

预览用的 `result.url` 是 `URL.createObjectURL` 产物，**页面卸载/调用 `dispose()` 后即失效**。要长期回看请用 `listScreenRecords` 返回的 `url`（后端地址），而非本地 objectURL。

### 7.6 不支持环境

`record.isSupported()` 为 `false`（非安全上下文 / 老浏览器）时，`start()` 抛错且 UI 应禁用按钮、给出提示文案（见演示页 `van-notice-bar`）。

- **安装插件**：`createScreenRecordPlugin({ autoUpload, uploader?, deps?, defaultMeta? })` → `app.use(...)`（③ 章）
- **取实例**：`useScreenRecord()`（组件/脚本任意处，单例）
- **手动录屏**：`record.start(opts)` / `record.pause()` / `record.resume()` / `record.stop()`（③ 章）
- **业务包裹**：`record.recordOperation(fn, opts)`（③ 章，推荐）
- **手动上传**：`record.upload(uploader?)`（④.4）
- **订阅状态**：`record.on(cb)` → 取消 `off()`（③.4）
- **能力探测**：`record.isSupported()`
- **替换上传**：`ScreenRecordUploader` 注入 `createScreenRecordPlugin({ uploader })` 或单次 `start({ uploader })`（⑤.2）
- **后端接口**：`uploadScreenRecord` / `listScreenRecords` / `blobToBase64`（`src/api/modules/demo-record.ts`，⑥ 章）
- **Mock 后端**：`src/mock/demo-record.ts` 的 `screenRecordMockRoutes`（⑥.4）
