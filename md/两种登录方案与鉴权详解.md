# 两种登录方案与鉴权机制详解

> 适用范围：`VantLogin`（vant 通用登录组件）与 `SiteLoginView`（ydl 站点登录页）两套登录实现。
> 配套代码：
> - 通用登录：`src/components/VantLogin.vue` + `src/composables/login/*` + `src/api/modules/login.ts`
> - 站点登录：`src/views/ydl/SiteLoginView.vue` + `src/composables/ydl/useSiteWecomLogin.ts` + `src/composables/ydl/useSitePasswordLogin.ts` + `src/api/modules/ydl/site-auth.ts`
> - 共享鉴权：`src/api/core/token.ts` + `src/api/core/http.ts` + `src/api/modules/ydl/site-client.ts` + `src/composables/usePermission.ts`

---

## 0. 总览：什么时候用哪套

| 维度 | VantLogin（通用登录） | SiteLoginView（站点登录） |
| --- | --- | --- |
| 面向系统 | vant / PICC 通用移动端 | ydl 旧站（JeecgBoot 体系，独立封装） |
| 后端格式 | vant 包络 `{ code, data, message }` | ydl 包络 `{ success, message, code, result }` |
| 后端 baseURL | `/api`（mock：src/mock/login.ts） | `/site-api`、`/wx-api`（mock：src/mock/ydl-site-auth.ts） |
| 登录方式 | 验证码 / 密码 / 微信 / 企业微信 + 找回密码 | 企业微信 OAuth（整页跳转）/ 账号密码（md5 + 图形验证码） |
| 组件耦合 | 自包含组件，可直接 `<VantLogin @success />` | 页面自实现 UI，复用独立 composable |
| 典型使用 | 演示 / 通用业务登录 | ydl 子系统统一入口 |

两者**共用同一套鉴权内核**（`core/token.ts` 的 `getToken/setToken`、请求拦截器注入、401 跳登录），因此"免登录联调、token 头字段名、本地存储 key"等配置对两套完全通用，详见第 4 节。

## 1. 方案一：VantLogin 通用登录

### 1.1 能力与入口

| 分类 | key | 入口 | 说明 |
| --- | --- | --- | --- |
| 表单类 | `sms` | 卡片 Tab | 短信验证码（滑块校验 + 60s 倒计时） |
| 表单类 | `password` | 卡片 Tab | 账号 + 密码 + 图形验证码 |
| OAuth 类 | `wechat` | 底部图标 | 微信扫码授权 |
| OAuth 类 | `wecom` | 底部图标 | 企业微信扫码授权 |
| 辅助 | 找回密码 | 密码页下方链接 | 手机号 + 验证码 + 新密码（弹窗） |

### 1.2 目录与职责（按登录方式拆分，互不耦合）

```
src/composables/login/
├── index.ts            # 统一出口
├── useLoginCore.ts     # 共用：loading / toast / doLogin / 结果派发（setToken + setUserInfo + emit）
├── useLoginConfig.ts   # 配置解析：可用方式/默认/标题 + ORDER / METHOD_META / activeMethod
├── useSmsLogin.ts      # 短信验证码登录
├── usePasswordLogin.ts # 密码登录（图形验证码）
├── useOAuthLogin.ts    # 微信/企业微信 OAuth（弹窗 / 整页跳转）
└── useForgotPassword.ts# 找回密码弹窗
```

`VantLogin.vue` 只负责：声明 props/emits、组装 composables、模板渲染、样式。修改某一种登录只改对应 `useXxx.ts`。

### 1.3 配置来源优先级

```
props 覆盖  >  后端 GET /login/config  >  内置默认值
```

若默认方式是 OAuth（底部入口，不适合做初始 Tab），且存在表单方式，会自动回退到第一个表单方式。

### 1.4 登录成功后的鉴权落库（关键）

所有登录方式最终都走 `useLoginCore.doLogin`：

```
doLogin(fn, method)
  ├─ showLoadingToast('登录中...')
  ├─ result = await fn()                 // 调用 loginBySms / loginByPassword / OAuth 回传
  ├─ setToken(result.token)              // 写入本地存储（见第 4 节）
  ├─ setUserInfo(result.userInfo)        // 写入本地存储，供「我的」页回显
  ├─ closeToast + toast('登录成功')
  └─ emit('success', result)             // 页面层据此跳 redirect 或弹窗
```

微信/企业微信在 `useOAuthLogin` 里通过 `postMessage` / `sessionStorage` 收口后，同样调用 `persistOAuth(result)`（= `setToken` + `setUserInfo`）再 `emit('success')`。

### 1.5 真实 OAuth 前置（外部配置）

走真实扫码并拉回真实用户信息需满足：`.env` 配齐 `WECHAT_*` / `WECOM_*` 凭证、`demoMode=false`、用**公网 HTTPS 域名**打开、后台登记回调域名与 `OAUTH_REDIRECT_BASE` 一致、并放好 `WW_verify_*.txt` 校验文件。本地预览可把 `demoMode` 设为 `true` 强制演示降级（无需 https / 可信域名）。详见 `md/VantLogin登录说明.md` 第八节。

## 2. 方案二：SiteLoginView 站点登录

### 2.1 两种登录方式

| Tab | 方式 | 说明 |
| --- | --- | --- |
| 左「企业微信登录」 | 企业微信 OAuth 整页跳转 | 无 code → 整页跳授权；回跳带 `code` → 换 token |
| 右「密码登录」 | 账号 + 图形验证码 + md5 密码 | 旧站约定密码需 md5 |

登录成功后 `router.replace(redirect)`（`route.query.redirect || '/ydl'`）。

### 2.2 目录与职责

```
src/views/ydl/SiteLoginView.vue              ← UI + 编排（不直接调接口）
src/composables/ydl/useSiteWecomLogin.ts     ← 企业微信 OAuth 跳转 / code 换 token
src/composables/ydl/useSitePasswordLogin.ts  ← 验证码 + md5 + 登录
src/api/modules/ydl/site-auth.ts             ← 接口定义
src/api/modules/ydl/site-client.ts           ← HTTP 客户端（baseURL / 401 跳登录）
src/api/core/token.ts                        ← token 读写
src/composables/usePermission.ts             ← loadPermissionsByToken 拉权限
src/mock/ydl-site-auth.ts                    ← mock 数据（/site-api、/wx-api）
```

分层原则：页面只做 UI 与编排，所有网络请求经 composable → `site-auth.ts` → `siteClient`。

### 2.3 企业微信登录流程（useSiteWecomLogin.start）

```
① 当前 URL 无 code
     └─ getAuthUrl({ wxAppId, redirect }) 拿授权地址
        └─ location.href = authUrl   // 整页跳转，本函数 return { ok:false }（不再往下走）

② 企业微信回跳带 code
     └─ getWxUserInfo({ wxAppId, code }) 用 code 换 token
        ├─ 内层 res.code === '00' → setToken + getSiteUserInfo(可选，补全档案) + setUserInfo
        │                         + loadPermissionsByToken → return { ok:true }
        ├─ res.code === '01'      → return { ok:false, code:'01', socialId, wxAuthId }  // 未绑定
        └─ 其它                    → return { ok:false, code, msg }                      // 未注册/失败
```

页面层把"结果 → 跳转 / 切密码 Tab"的逻辑抽成共享的 `finishWecom(res)`（`SiteLoginView.vue`）：

- `res.ok` → `showToast('登录成功')` + `router.replace(redirect)`
- `res.code === '01'` → 写入 `socialId`，切到密码 Tab，提示「请先绑定账号」（密码登录时把 `socialId` 带上去完成绑定）
- `res.code` 其它 → `showToast(res.msg || '企业微信登录失败')`

`onWecomClick`（按钮点击，无 code 走跳转分支）与 `onMounted`（回跳带 code 走换 token 分支）都复用 `finishWecom`，避免结果分支重复。

### 2.4 账号密码登录流程（useSitePasswordLogin）

```
refreshCaptcha()
  └─ getCaptchaImg() → 有 res.img（真实后端 base64 图）则渲染 captchaImg；
                       无 img（mock 字符）则字符回退（本站只渲染 captchaImg）

submit({ username, password, captcha, socialId? })
  └─ password 经 md5 → userLogin({ username, password:md5, captcha, captchaKey, socialId? })
     └─ setToken(token) + loadPermissionsByToken(token)
```

`captchaKey` 由 `refreshCaptcha` 暂存在闭包，提交时一并传给后端校验验证码归属。

### 2.5 接口契约（site-auth.ts）

| 功能 | 函数 | 方法 | 路径 | 业务码 |
| --- | --- | --- | --- | --- |
| 企业微信授权地址 | `getAuthUrl` | GET | `/cp/wxAuth/getAuthUrl` | `code:0` |
| 企业微信 code 换 token | `getWxUserInfo` | POST | `/cp/wxAuth/getWxUserInfo` | 内层 `result.code`：`'00'/'01'/'02'` |
| 图形验证码 | `getCaptchaImg` | GET | `/sys/captchaImage` | `code:200` |
| 账号密码登录 | `userLogin` | POST | `/sys/social/wxLogin` | `code:200` |
| 拉权限 | `getUserPermissionByToken` | GET | `/sys/permission/getUserPermissionByToken` | `code:200` |
| 登出 | `siteLogout` | POST | `/sys/logout` | `code:200`（带 `__skipAuthFail`） |

响应包络由 `ydlFormat` 适配器统一处理，兼容双语义：业务接口 `success===true && code===200`；鉴权接口（微信）`code===0`。`401/510` → `clearAuth()` + 跳 `/ydl/login?redirect=<当前路径>`（见 `site-client.ts` 的 `onAuthFail`）。

## 3. 共享请求层与 401 跳登录

两套登录的 HTTP 客户端都基于 `core/http.ts` 的 `createClient` 工厂：

- **请求拦截器**：读取 `getToken()`，若有值则注入 `config.headers[TOKEN_HEADER]`（`TOKEN_HEADER` = `VITE_TOKEN_HEADER`，默认 `X-Access-Token`）。
- **响应拦截器**：`401/403/510` 触发 `onAuthFail` 跳登录（站点侧还会先 `clearAuth()`）。
- **统一异常**：非成功响应抛 `BizError(code, message)`，由调用方 `catch`。

## 4. 共享鉴权机制（core/token.ts）★ 免登录联调核心

### 4.1 token 读写 API

| 函数 | 行为 |
| --- | --- |
| `getToken()` | 优先返回 `DEV_TOKEN`（配置了预置 token 时）；否则读 `localStorage[TOKEN_STORAGE_KEY]` |
| `setToken(t)` | 配置了 `DEV_TOKEN` 时为 **no-op**（保护预置 token 不被覆盖）；否则写 `localStorage` |
| `clearToken()` / `clearAuth()` | 清 token（登出用） |
| `getUserInfo()` / `setUserInfo()` | 登录用户档案（「我的」页回显） |
| `initDevToken()` | 应用启动时调用：仅当 `DEV_TOKEN` 有值且本地无 token 时写入 `localStorage` |

### 4.2 可配置项（环境变量）

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `VITE_TOKEN_HEADER` | `X-Access-Token` | 请求头中携带 token 的字段名（可改为 `Authorization` 等） |
| `VITE_TOKEN_STORAGE_KEY` | `app_token` | 浏览器本地存储 token 的 key |
| `VITE_DEV_TOKEN` | 空 | **开发期预置 token**：强制 token，跳过登录联调真实后端 |
| `VITE_MOCK_CP` | 未设 | 仅把"站点鉴权链路"（/cp 与 /sys）强制走本地 mock |

> 这些变量写在根 `.env`（基础默认值）与 `.env.development` / `.env.zyn` 等模式文件里，构建时经 `vite.config.ts` 的 `define` 注入 `import.meta.env.*`。

### 4.3 VITE_DEV_TOKEN：免登录联调

开发环境后端可用、但不想走完整登录流程时，配一个真实 token：

```bash
# .env.development 或 .env.zyn
VITE_DEV_TOKEN=eyJhbGciOiJIUzI1NiJ9.xxxxx
```

行为：

1. `src/main.ts` 挂载前调用 `initDevToken()`，把 token 写入 `localStorage[TOKEN_STORAGE_KEY]`。
2. 之后所有请求经请求拦截器自动携带该 token（`X-Access-Token` 头）。
3. 它是**强制 token**：任何 `setToken`（包括真实登录 / mock 登录返回的 token）都不会覆盖它，因此不会被登录流程"顶替"。
4. 仅当本地原本无 token 时才注入，不覆盖真实登录态。生产环境**不要**配置。

> 注意：后端多为 JeecgBoot，token 是"JWT 签名 + Redis 服务端会话"双重校验。JWT 的 `exp` 未过期不代表后端仍认——若 Redis 会话已失效（服务重启 / TTL 到期），后端返回 `401 认证失败`。此时需重新从有效登录拿一枚新 token 更新 `VITE_DEV_TOKEN`。

### 4.4 与 VITE_MOCK_CP 的关系

- `VITE_MOCK_CP=true`（仅 dev / development 模式）：把"站点鉴权链路"整体走本地 mock——`siteWxClient(/cp/wxAuth/...)` 与 `siteClient(/sys/...)` 的 baseURL 在 `vite.config.ts` 被覆盖为 `/wx-api`、`/site-api`，由 mock 中间件拦截。这样 mock 登录换来的 token 与 mock 权限接口能对上，不会报"认证失败"。其余接口（vant `/api`、ydl `/ydl-api`）仍走真实后端代理。
- 若同时配了 `VITE_DEV_TOKEN`：在 mock-cp 模式下，`DEV_TOKEN` 仍是强制 token（getToken 优先返回它），但站点鉴权链路走 mock 时不依赖真实 token，故二者可并存；真实联调（`dev:zyn`）时则靠 `VITE_DEV_TOKEN` 免登录。

## 5. 开发模式与运行命令

| 命令 | mode | 行为 |
| --- | --- | --- |
| `pnpm dev`（= `vite`） | - | 等同 `development`；但脚本里通常用 `dev:development` |
| `pnpm dev:development` | development | 站点鉴权链路走 mock（需 `VITE_MOCK_CP=true`，见 `.env.development`） |
| `pnpm dev:zyn` | zyn | 全部走真实后端（`.env.zyn` 配真实 baseURL + `VITE_DEV_TOKEN` 免登录） |
| `pnpm dev:mock` | mock | 全部接口走 mock |

> 关键坑：`.env.zyn` 里**不要**写 `VITE_MOCK_CP=true`，否则 `vite.config.ts` 会禁用整个 dev proxy，导致请求打到 dev server 自身（表现为 404 / SPA 兜底 / 网络错误）而非转发到真实后端。

### 5.1 代理自动生成（vite.config.ts）

`vite.config.ts` 从 baseURL 环境变量自动解析前缀与目标，dev 下把绝对地址覆盖为相对前缀走同源代理（解决跨域 + 剥掉 Origin/Referer 防 JeecgBoot CORS 403）：

| 环境变量 | 示例值 | 生成代理 | 覆盖为（dev 相对） |
| --- | --- | --- | --- |
| `VITE_API_BASE_URL` | `http://40.33.32.20:8090/is` | `/is → 40.33.32.20:8090` | `/is` |
| `VITE_SITE_API_BASE_URL` | `http://40.33.32.20:8090/is` | `/is → 40.33.32.20:8090` | `/site-api`（mock-cp） |
| `VITE_SITE_WX_API_BASE_URL` | `http://40.33.32.20:8090/wx` | `/wx → 40.33.32.20:8090` | `/wx-api`（mock-cp） |
| `VITE_YDL_API_BASE_URL` | `http://40.33.32.20:8090/is` | `/is → 40.33.32.20:8090` | `/is` |

纯 mock 模式（`mode==='mock'`）不启用 proxy（全部走 mock）；`mock-cp` 与 `zyn` 启用 proxy 连真实后端。

## 6. 排错速查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 请求 URL 是 `5173` 且返回 404 / HTML | proxy 被禁用（`VITE_MOCK_CP` 误配在 zyn） | 移除 `.env.zyn` 的 `VITE_MOCK_CP`，重启 `dev:zyn` |
| 后端返回 `401 认证失败` | `VITE_DEV_TOKEN` 被后端拒绝（Redis 会话失效 / 非本实例签发） | 用有效登录重新拿一枚 token 更新 `VITE_DEV_TOKEN`，重启 |
| 企业微信点击无反应（dev） | 未配 `VITE_SITE_OAUTH_REDIRECT_BASE`，用 `location.origin` 跳但无可信域名 | 真实联调配域名；演示依赖 mock `getAuthUrl` 直接回跳 |
| 验证码区域空白 | 模板只渲染 `captchaImg`；后端返回字符（`img` 为空）则无图 | 确认后端返回 `img`（base64 图）；或补 `captchaItems` 渲染 |
| 验证码图破图 | `captchaSrc` MIME 推断未命中 | 检查 base64 头部，补 `head.startsWith(...)` 分支 |
| 登录后权限为空 | `loadPermissionsByToken` 失败 / token 无效 | 看 Network 中 `/sys/permission/getUserPermissionByToken` 返回 |
| 401 后反复跳登录 | `onAuthFail` 触发；token 过期或接口需鉴权 | 检查请求是否错误携带过期 token |

## 7. 扩展指南

- **新增一种 vant 登录方式**：`api/modules/login.ts` 加 `LoginMethod` + 接口 → `useLoginConfig.ts` 的 `ORDER`/`METHOD_META` 补元信息 → 新建 `useXxxLogin.ts`（复用 `useLoginCore.doLogin`）→ `VantLogin.vue` 解构并补模板。
- **改站点登录密码校验**：`onSubmitPassword` 前置校验；md5 在 `useSitePasswordLogin.submit` 内完成。
- **新增站点登录 Tab**：`activeTab` 联合类型加值 → `.card-tabs` 加按钮 → 加面板 `v-else-if` → 加对应 composable。
- **改登录后行为**：统一在 `useLoginCore.doLogin` 处理即全局生效；站点侧则是 `finishWecom` + `useSiteWecomLogin` / `useSitePasswordLogin` 的 `setToken + loadPermissionsByToken`。
- **改主色 / 品牌**：`#d71920` 集中在 `<style scoped>` 顶部令牌，全局替换即可。
